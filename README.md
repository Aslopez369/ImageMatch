# ImageMatch

**给一张样图，在一个图片文件夹里找出最像的前 N 张。**

面向「近似重复」场景：同一张照片的压缩版、缩放版、调色版、加过水印的版本、被裁剪或旋转过的版本。

纯 CPU 运行，不需要 GPU，不需要下载模型。

---

## 为什么又造一个轮子

现成的去重工具走的是另一条路：

| 工具 | 输入 | 输出 |
|---|---|---|
| czkawka / difPy / imgdupes / dupeGuru | 一个或几个**文件夹** | 哪些图彼此相似（分组） |
| clip-retrieval / immich | 一张图或一句话 | 语义上相似的图 |
| **ImageMatch** | **一个文件夹 + 一张样图** | **最像的前 N 张，带分数** |

第一条路回答不了「我手上这张图，库里最像的是哪几张」。第二条路（CLIP 语义检索）判断的是「是不是同一类东西」，它会把十张不同的猫照片判定为高度相似，反而分不清「这张是不是那张的裁剪版」。

近似重复需要的是像素级的结构一致性，这个空档值得单独做一个工具。

## 原理

### 阶段一：感知哈希粗筛

每张图计算 4 个 64 位指纹：

- **pHash** — 32×32 灰度做 DCT，取左上 8×8 低频系数与中位数比较
- **中心裁剪 pHash** — 先裁掉 12.5% 边框再算 pHash，用来兜住「被裁剪过的同一张图」
- **dHash** — 9×8 灰度图的水平梯度
- **aHash** — 8×8 灰度的均值阈值

比对方式是异或后数 1 的个数（汉明距离）。一万张图的排序在毫秒级完成，因为这一步是纯位运算。

对压缩、改尺寸、调色、加水印、轻微模糊都稳定。

### 阶段二：局部特征复核

对粗筛出的 100~600 张候选，用 ORB 特征匹配 + RANSAC 单应性估计做几何校验，再叠加 64×64 灰度的归一化互相关（NCC）。

这一步才是识别**裁剪、旋转、镜像**的关键——哈希对这类变化不敏感地失效。

### 融合

```
base = 0.40·s_pHash + 0.13·s_dHash + 0.22·NCC + 0.25·ORB
score = max(base, 0.85·ORB)   # 当 ORB ≥ 0.8 时
```

第二条规则来自一个实际踩到的坑：裁剪图和旋转图的 ORB 得分是 1.00（几何上完美吻合），但 pHash 距离很大、NCC 很低，加权平均后会被拖到 40 分上下，排在无关图附近。改用「几何校验高置信时取更高分」之后才正常。

## 实测

测试图库：60 张互不相关的合成图 + 目标图的 7 个变体，查询图为目标图的调色版。

| 变体 | 得分 |
|---|---|
| 加水印 | 97.5 |
| 缩放 + JPEG 质量 72 | 97.0 |
| 高斯模糊 σ=2.0 | 97.0 |
| 提亮 1.25× | 96.5 |
| 中心裁剪 70% | 85.0 |
| 旋转 12° | 85.0 |
| **无关图（最高分者）** | **19.8** |

8 个变体全部进入前 8，与无关图之间是断崖式分界。

## 安装

需要 **Python 3.9+**，且安装时勾选了 `tcl/tk`（图形界面依赖它）。

Windows 下双击 `setup.bat` 即可，它会创建 `.venv` 并装好依赖。

手动：

```bash
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

依赖只有三个：Pillow、numpy、opencv-python-headless。

## 使用

### 图形界面

双击 `run.bat`。选文件夹、选样图、填返回张数，点「开始检索」，结果会以网页报告打开。

### 命令行

```bash
python find_similar.py --folder "D:\图片库" --query "D:\样图.jpg" --top 20
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--top N` | 返回前 N 张，默认 10 |
| `--threshold 70` | 只保留分数不低于 70 的结果 |
| `--copy-to 目录` | 把命中的图复制出来，文件名带排名和分数 |
| `--rebuild` | 忽略缓存，强制重建索引 |
| `--no-orb` | 关闭 ORB 复核，只用哈希（更快，但裁剪/旋转会失效） |
| `--workers N` | 建索引的线程数 |

### 输出

- `output/report_*.html` — 自包含的报告，缩略图已内嵌，可直接分享
- `output/report_*.json` — 结构化结果，方便二次处理

---

## 分数怎么读

| 分数 | 含义 |
|---|---|
| ≥ 88 | 几乎确定是同一张 |
| 72 ~ 88 | 很可能是同一张（裁剪、旋转通常落在这里） |
| 55 ~ 72 | 内容相关，值得人工看一眼 |
| < 55 | 相似度较低 |

阈值建议：判断「是否重复」用 70，宁可放过不要误杀用 80。

## 性能

在 8 核 CPU 上实测（含首次建索引）：

| 图库规模 | 总耗时 |
|---|---|
| 67 张 | 2.6 秒 |
| 1005 张 | 8.6 秒 |

索引缓存在 `cache/` 下，按「路径 + 文件大小 + 修改时间」增量更新。第二次查询同一个目录基本秒出，新增的图只计算新的。一万张的首次建库约 1 分钟。

## 局限

- **不支持 HEIC / RAW**，iPhone 原图需要先转 JPG
- **翻转 + 裁剪**这类叠加变换，分数会掉到 60~70
- 只解决「近似重复」，**不做语义检索**。要按内容找（都是猫、都是海边）应该用 CLIP 系方案
- 图形界面基于 Tkinter，macOS / Linux 上需要自行确认 tkinter 可用
